# go_auth: example of building an Authentication system in Go

A robust authentication system built with Go, implementing JWT-based authentication using RSA public/private key cryptography.[2][1]

## Overview

This authentication service provides secure token-based authentication using asymmetric RSA signing, where tokens are created with a private key and validated with a public key. This approach ensures that only the server can generate valid tokens while allowing multiple services to verify them independently.[4][3][2]

## Features

- **JWT Authentication**: Secure token-based authentication using JSON Web Tokens[3]
- **RSA Signing**: Asymmetric cryptography with RS256 algorithm for enhanced security[2][4]
- **Token Generation**: Create signed JWT tokens with custom claims[3]
- **Token Validation**: Verify token authenticity using public key[2]
- **Modular Design**: Clean architecture following Go best practices[5]

## Prerequisites

- Go 1.16 or higher
- OpenSSL (for key generation)

### API Endpoints

The service typically exposes the following endpoints:

- `POST /auth/register` - Register a new user
- `POST /auth/login` - Authenticate and receive JWT token
- `POST /auth/refresh` - Refresh an expired token
- `GET /auth/validate` - Validate an existing token

## Security Keys

### Important Security Notice

⚠️ **The project includes sample public and private keys for development purposes only**.[1]

**In production environments:**
- Generate your own RSA key pairs[1][2]
- Store keys securely (environment variables, secret management services, or encrypted storage)[1]
- **Never commit private keys to version control**[1]
- Restrict access to keys to authorized personnel only[1]

### Generating Your Own Keys

Generate a new RSA key pair using OpenSSL:[4][2]

```bash
# Generate 4096-bit RSA private key
openssl genrsa -out id_rsa 4096

# Extract public key from private key
openssl rsa -in id_rsa -pubout -out id_rsa.pub
```

## Configuration

Create a `.env` file in the root directory with the following variables:

```env
PORT=8080
PRIVATE_KEY_PATH=./keys/id_rsa
PUBLIC_KEY_PATH=./keys/id_rsa.pub
TOKEN_EXPIRY=3600
REFRESH_TOKEN_EXPIRY=86400
```

## JWT Token Structure

Tokens generated by this service follow the standard JWT format:[3]

**Header**
```json
{
  "alg": "RS256",
  "typ": "JWT"
}
```

**Payload** (Claims)
```json
{
  "sub": "user_id",
  "name": "User Name",
  "iat": 1234567890,
  "exp": 1234571490
}
```

**Signature**
```
RS256(base64UrlEncode(header) + "." + base64UrlEncode(payload), private_key)
```

## Best Practices

- Always use HTTPS in production to prevent token interception[7][3]
- Implement token refresh mechanisms for better user experience[3]
- Set appropriate token expiration times[3]
- Store tokens securely on the client side (httpOnly cookies recommended)[3]
- Implement rate limiting to prevent brute force attacks[7]
- Validate all input data before processing[7]
